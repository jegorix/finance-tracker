# Теоретическая часть к лабораторной работе

## Введение

В этой теоретической части рассматриваются темы, которые часто встречаются в лабораторных работах по Java, Spring Data и работе с данными:

- JPQL и native query
- Java Collections Framework
- `ArrayList` vs `LinkedList`
- `Collection` vs `Collections`
- `HashMap` и метод `put()`
- `equals()` и `hashCode()` для объекта-ключа `HashMap`

Ниже каждая тема разобрана отдельно и без привязки к конкретному проекту.

## 1. JPQL и native query

### 1.1 Что такое JPQL

JPQL (`Java Persistence Query Language`) — это язык запросов, используемый в JPA. Он предназначен для работы не с таблицами базы данных напрямую, а с Java-сущностями и их полями.

Это означает:

- в SQL обычно пишут имена таблиц и колонок
- в JPQL пишут имена entity-классов и их полей

Например:

```jpql
SELECT e FROM Employee e
WHERE e.salary > 1000
```

Здесь:

- `Employee` — это сущность Java
- `salary` — поле сущности

JPQL не зависит от конкретной физической схемы базы так напрямую, как обычный SQL.

### 1.2 Основная идея JPQL

JPQL работает на уровне объектной модели.

Если в приложении есть связь:

- `Order -> Customer`

то в JPQL можно обращаться к ней как к полю объекта:

```jpql
SELECT o FROM Order o
WHERE o.customer.name = :name
```

Это удобно, потому что разработчик мыслит сущностями предметной области, а не таблицами и внешними ключами.

### 1.3 Преимущества JPQL

JPQL полезен по нескольким причинам:

- он ближе к объектной модели Java
- он интегрирован в JPA/Hibernate
- он скрывает часть деталей физической схемы БД
- он обычно легче читается в приложениях, где используется ORM

JPQL особенно удобен, когда запросы естественно выражаются через связи между сущностями.

### 1.4 Ограничения JPQL

JPQL не всегда удобен:

- некоторые сложные SQL-конструкции выразить трудно
- не все возможности конкретной СУБД доступны напрямую
- иногда нужен более точный контроль над тем, какой SQL реально пойдёт в базу

Именно поэтому в JPA существует возможность использовать native query.

### 1.5 Что такое native query

Native query — это обычный SQL-запрос, который пишется в том виде, в каком его понимает конкретная база данных.

Например:

```sql
SELECT e.*
FROM employees e
JOIN departments d ON d.id = e.department_id
WHERE d.name = 'IT'
```

Здесь уже используются:

- реальные таблицы
- реальные колонки
- реальные внешние ключи

То есть native query работает на уровне физической схемы БД, а не на уровне Java-сущностей.

### 1.6 Преимущества native query

Native query полезен, когда:

- требуется максимально точный контроль над SQL
- нужны функции, характерные для конкретной СУБД
- запрос сложный и неудобен в JPQL
- важно использовать оптимизированный SQL в явном виде

### 1.7 Ограничения native query

Минусы native query:

- он сильнее зависит от структуры БД
- он хуже переносится между разными СУБД
- при изменении схемы БД такой код чаще приходится править вручную
- он менее объектно-ориентирован, чем JPQL

### 1.8 Сравнение JPQL и native query

JPQL:

- работает с entity-классами
- использует поля сущностей
- ближе к JPA-модели
- более абстрактен

Native query:

- работает с таблицами и колонками
- использует обычный SQL
- ближе к СУБД
- даёт более явный контроль над запросом

### 1.9 Когда использовать JPQL, а когда native query

JPQL стоит использовать, если:

- запрос естественно описывается через сущности
- нужен код на уровне ORM
- важна читаемость в рамках JPA-приложения

Native query стоит использовать, если:

- запрос слишком сложен для JPQL
- нужны специфические SQL-возможности
- важен ручной контроль над SQL

### 1.10 Краткий вывод

JPQL и native query решают одну и ту же задачу — получение данных из базы, но делают это на разных уровнях абстракции:

- JPQL — через сущности
- native query — через SQL и таблицы

## 2. Java Collections Framework

### 2.1 Что такое Java Collections Framework

Java Collections Framework — это стандартный набор интерфейсов, классов и алгоритмов для хранения и обработки групп объектов в памяти.

Проще говоря, это библиотека структур данных в Java.

Она избавляет разработчика от необходимости каждый раз заново реализовывать:

- списки
- множества
- очереди
- словари

### 2.2 Зачем нужен Collections Framework

Без него работа с наборами данных была бы слишком трудоёмкой.

Разработчику пришлось бы самому писать:

- динамические массивы
- связные списки
- структуры поиска
- алгоритмы сортировки
- вспомогательные операции над коллекциями

Collections Framework предоставляет всё это в готовом и стандартизированном виде.

### 2.3 Основные интерфейсы

Ключевые интерфейсы:

- `Collection`
- `List`
- `Set`
- `Queue`
- `Deque`
- `Map`

Важно понимать:

- `Map` обычно относят к Collections Framework
- но формально `Map` не наследуется от `Collection`

### 2.4 Основные реализации

На практике часто используются:

- `ArrayList`
- `LinkedList`
- `HashSet`
- `LinkedHashSet`
- `TreeSet`
- `HashMap`
- `LinkedHashMap`
- `TreeMap`

### 2.5 Почему Collections Framework важен

Он важен потому, что почти любое нетривиальное Java-приложение постоянно работает с наборами объектов:

- читает их
- фильтрует
- сортирует
- группирует
- хранит в памяти

Поэтому понимание коллекций — это базовая часть Java-разработки.

### 2.6 Основные свойства коллекций

Разные коллекции отличаются по нескольким параметрам:

- допускают ли дубликаты
- сохраняют ли порядок элементов
- насколько быстро ищут элементы
- насколько быстро добавляют и удаляют элементы
- как много памяти используют

Именно под задачу подбирается конкретная структура данных.

## 3. ArrayList vs LinkedList

### 3.1 Что такое ArrayList

`ArrayList` — это реализация интерфейса `List`, основанная на динамическом массиве.

Внутри элементы хранятся в массиве, который при необходимости увеличивается.

### 3.2 Свойства ArrayList

`ArrayList` удобен тем, что:

- быстро даёт доступ по индексу
- хорошо подходит для последовательного чтения
- обычно работает эффективно в типичных бизнес-сценариях

Но у него есть ограничения:

- вставка в середину может быть дорогой
- удаление из середины тоже может быть дорогим

Причина в том, что после вставки или удаления часть элементов приходится сдвигать.

### 3.3 Что такое LinkedList

`LinkedList` — это реализация `List`, основанная на связном списке.

Каждый элемент хранит:

- значение
- ссылку на следующий элемент
- ссылку на предыдущий элемент

### 3.4 Свойства LinkedList

Плюсы `LinkedList`:

- удобно вставлять или удалять элементы, если уже найдено нужное место
- можно использовать как очередь или двустороннюю очередь

Минусы:

- доступ по индексу медленный
- больше расход памяти
- часто хуже работает по производительности в обычных задачах

### 3.5 Сравнение ArrayList и LinkedList

`ArrayList` обычно лучше, если:

- часто нужен доступ по индексу
- часто нужен проход по списку
- элементы в основном добавляются в конец

`LinkedList` может быть полезен, если:

- важны частые вставки и удаления
- нужен интерфейс очереди или дека

### 3.6 Почему ArrayList обычно выбирают чаще

В реальных приложениях `ArrayList` чаще оказывается предпочтительнее, потому что:

- чтение встречается чаще, чем сложные вставки в середину
- доступ по индексу быстрее
- массивы лучше используют кеш процессора

### 3.7 Вывод

Если нет специальной причины брать `LinkedList`, по умолчанию чаще выбирают `ArrayList`.

## 4. Collection vs Collections

### 4.1 Что такое Collection

`Collection` — это интерфейс.

Он задаёт базовый контракт для набора элементов.

В нём определяются общие операции:

- добавить элемент
- удалить элемент
- проверить размер
- проверить, пустая ли коллекция
- перебрать элементы

От `Collection` наследуются:

- `List`
- `Set`
- `Queue`

### 4.2 Что такое Collections

`Collections` — это utility-класс.

Он содержит статические методы для работы с коллекциями.

Например:

- `Collections.sort(list)`
- `Collections.emptyList()`
- `Collections.unmodifiableList(list)`
- `Collections.singleton(value)`

### 4.3 Главная разница

Разница очень простая:

- `Collection` — интерфейс
- `Collections` — класс с полезными статическими методами

### 4.4 Почему это часто путают

Они отличаются всего одной буквой, поэтому их часто смешивают.

Но смысл у них разный:

- `Collection` описывает тип данных
- `Collections` предоставляет операции над коллекциями

### 4.5 Вывод

Если спрашивают разницу, короткий ответ такой:

`Collection` — это базовый интерфейс для группы объектов, а `Collections` — вспомогательный класс с набором статических методов для работы с коллекциями.

## 5. HashMap и метод put()

### 5.1 Что такое HashMap

`HashMap<K, V>` — это структура данных для хранения пар:

- ключ
- значение

Например:

```java
Map<String, Integer> map = new HashMap<>();
map.put("A", 10);
map.put("B", 20);
```

Здесь:

- `String` — тип ключа
- `Integer` — тип значения

### 5.2 Для чего нужен HashMap

`HashMap` нужен для быстрого поиска значения по ключу.

Типичные операции:

- `put(key, value)`
- `get(key)`
- `containsKey(key)`
- `remove(key)`

в среднем работают быстро.

### 5.3 Общий принцип работы HashMap

В упрощённом виде механизм такой:

1. Для ключа вычисляется `hashCode()`
2. На основе этого хеша выбирается бакет
3. Внутри бакета выполняется проверка через `equals()`
4. Если ключ уже есть, значение обновляется
5. Если ключа нет, создаётся новая запись

### 5.4 Что делает put()

Метод `put(key, value)`:

- добавляет новую пару, если такого ключа ещё нет
- обновляет значение, если такой ключ уже существует

Пример:

```java
Map<String, Integer> map = new HashMap<>();
map.put("X", 1);
map.put("X", 5);
```

Результат:

```java
{"X"=5}
```

То есть повторный `put()` для того же ключа заменяет старое значение.

### 5.5 Почему HashMap удобен

Он удобен, когда нужно:

- быстро искать значение по ключу
- хранить словарь соответствий
- кэшировать результаты
- запоминать уже обработанные данные

### 5.6 Ограничения HashMap

Нужно помнить:

- порядок элементов не гарантируется
- он не является потокобезопасным
- корректность сильно зависит от правильной реализации `equals()` и `hashCode()` у ключа

### 5.7 Чем HashMap отличается от TreeMap и LinkedHashMap

`HashMap`:

- не гарантирует порядок
- ориентирован на быстрое хеш-основанное хранение

`LinkedHashMap`:

- сохраняет порядок вставки

`TreeMap`:

- хранит ключи в отсортированном виде
- обычно работает медленнее, чем `HashMap`, но поддерживает упорядоченность

## 6. equals() и hashCode() для объекта-ключа HashMap

### 6.1 Почему это важно

Если объект используется как ключ в `HashMap`, то он должен корректно определять:

- равенство объектов
- хеш объекта

Именно за это отвечают `equals()` и `hashCode()`.

### 6.2 Что делает equals()

Метод `equals()` отвечает на вопрос:

"Являются ли два объекта логически равными?"

То есть не обязательно речь идёт о том, что это один и тот же объект в памяти.

Речь идёт о логическом равенстве по содержимому.

### 6.3 Что делает hashCode()

`hashCode()` возвращает целое число, которое используется хеш-структурами данных для первичного распределения объектов.

Это не уникальный идентификатор, а числовое представление объекта для ускорения поиска.

### 6.4 Главное правило

Если два объекта равны по `equals()`, то у них обязательно должен быть одинаковый `hashCode()`.

Это фундаментальное правило для корректной работы `HashMap`.

Обратное неверно:

- одинаковый `hashCode()` не гарантирует, что объекты равны

### 6.5 Почему одного equals() недостаточно

Если определить только `equals()`, но не реализовать согласованный `hashCode()`, могут возникнуть ошибки:

- объект не находится в `HashMap`, хотя логически он там уже есть
- одинаковые ключи попадают в разные бакеты
- кэш или словарь начинают работать некорректно

### 6.6 Что значит корректная реализация

Корректная реализация означает:

- в `equals()` сравниваются поля, определяющие логическую идентичность объекта
- в `hashCode()` используются те же поля

То есть оба метода должны быть согласованы.

### 6.7 Типичный пример

Если ключ состоит из нескольких параметров, например:

- имя
- дата
- номер страницы

то именно эти параметры должны участвовать:

- и в `equals()`
- и в `hashCode()`

Если какое-то поле забыть, начнутся логические ошибки.

### 6.8 Что будет, если сделать неправильно

Возможные проблемы:

- одинаковые логические ключи не будут находиться
- разные ключи могут ошибочно вести себя одинаково
- структура данных потеряет корректность

### 6.9 Вывод

Для объекта-ключа `HashMap` методы `equals()` и `hashCode()` обязательны и должны быть согласованы между собой.

## 7. Пагинация

### 7.1 Что такое пагинация

Пагинация — это разбиение большого набора данных на страницы.

Вместо того чтобы отдавать все данные сразу, система отдаёт только часть данных за один запрос.

### 7.2 Зачем нужна пагинация

Пагинация нужна, чтобы:

- уменьшить размер ответа
- снизить нагрузку на сервер
- ускорить передачу данных
- сделать интерфейс удобнее для пользователя

Если данных много, отдавать всё сразу обычно неэффективно.

### 7.3 Основные параметры пагинации

Чаще всего используются:

- `page` — номер страницы
- `size` — количество элементов на странице
- `sort` — порядок сортировки

Пример:

```http
GET /items?page=0&size=10&sort=name,asc
```

Это означает:

- первая страница
- по 10 элементов
- сортировка по имени по возрастанию

### 7.4 Что такое Pageable

В экосистеме Spring `Pageable` — это объект, который описывает параметры пагинации:

- номер страницы
- размер страницы
- сортировку

Он не содержит сами данные, а только параметры запроса к данным.

### 7.5 Что такое Page

`Page<T>` — это объект, который содержит:

- содержимое текущей страницы
- номер страницы
- размер страницы
- общее число элементов
- общее число страниц

То есть `Page<T>` — это результат paged-запроса вместе с метаданными.

### 7.6 Почему пагинация важна

Она делает работу с большими наборами данных практичной.

Без пагинации:

- ответы были бы слишком большими
- клиенты получали бы слишком много лишних данных
- производительность могла бы ухудшаться

### 7.7 Пагинация и сортировка

Пагинация почти всегда связана с сортировкой.

Если порядок элементов не определён, страничная выдача может быть нестабильной.

Поэтому обычно вместе с пагинацией задают `sort`.

### 7.8 Пагинация и кэширование

Если результаты запросов кэшируются, то параметры пагинации обязательно должны учитываться в ключе кэша.

Иначе:

- страница 0
- страница 1

могут ошибочно считаться одинаковыми.

То же самое относится к сортировке:

- разная сортировка должна считаться разными запросами

### 7.9 Вывод

Пагинация — это важный механизм оптимизации и удобства, который позволяет работать с большими объёмами данных порционно и предсказуемо.

## 8. Как все темы связаны между собой

Эти темы логически связаны.

Обычно общий процесс выглядит так:

1. Выполняется запрос к данным
2. Для получения данных используется JPQL или native query
3. Результат может быть разбит на страницы
4. Для хранения данных в памяти используются структуры Collections Framework
5. Для быстрого доступа по составному ключу может использоваться `HashMap`
6. Корректность работы `HashMap` зависит от `equals()` и `hashCode()`

То есть:

- JPQL и native query отвечают за доступ к данным
- пагинация отвечает за форму выдачи
- Collections Framework даёт структуры данных
- `HashMap` обеспечивает быстрый поиск в памяти
- `equals()` и `hashCode()` обеспечивают корректность ключей

## 9. Краткие ответы для устной защиты

### Что такое JPQL

JPQL — это язык запросов JPA, который работает с сущностями и их полями, а не напрямую с таблицами базы данных.

### Что такое native query

Native query — это обычный SQL-запрос, использующий реальные таблицы и колонки базы данных.

### Чем JPQL отличается от native query

JPQL работает на уровне entity-модели, а native query — на уровне SQL и физической схемы БД.

### Что такое Java Collections Framework

Это стандартный набор интерфейсов, классов и алгоритмов Java для хранения и обработки групп объектов.

### Разница между ArrayList и LinkedList

`ArrayList` основан на динамическом массиве и обычно лучше для чтения и доступа по индексу. `LinkedList` основан на связном списке и чаще нужен для более специфических сценариев.

### Разница между Collection и Collections

`Collection` — интерфейс, а `Collections` — utility-класс со статическими методами.

### Что делает HashMap.put()

`put()` добавляет новую пару ключ-значение или заменяет значение для уже существующего ключа.

### Зачем объекту-ключу нужны equals() и hashCode()

Они нужны для корректной работы `HashMap`, чтобы одинаковые ключи правильно находились и сравнивались.

### Что такое пагинация

Пагинация — это разбиение большого набора данных на страницы с помощью параметров `page`, `size` и `sort`.

## 10. Итог

Теоретическая основа этой темы строится на сочетании нескольких уровней:

- уровень доступа к данным: JPQL и native query
- уровень структур данных в памяти: Collections Framework и `HashMap`
- уровень корректности ключей: `equals()` и `hashCode()`
- уровень выдачи результата: пагинация

Понимание этих тем важно, потому что они часто используются вместе:

- при построении поисковых запросов
- при кэшировании результатов
- при работе с большими объёмами данных
- при проектировании эффективных серверных приложений
